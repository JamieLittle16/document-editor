# Product Roadmap

## R0 — Foundation

A robust engineering prototype that proves the architecture:

- process-isolated document engine;
- DOCX open/edit/save;
- paginated rendering/viewport;
- revisioned session and mutation envelope;
- recovery foundations;
- compatibility/performance laboratories.

## R1 — Daily driver

A polished editor for normal documents:

- rich formatting and styles;
- lists, tables, images;
- page layout, sections, headers/footers;
- search/navigation;
- spelling and grammar;
- PDF/print;
- reliable recovery/history;
- mature keyboard and application UX.

## R2 — Serious technical writing

- document-health diagnostics;
- terminology/consistency analysis;
- excellent equations;
- citations/cross-references/captions;
- publication checks;
- long-document navigation/performance;
- structured revision-safe AI assistance.

## R3 — Professional Word replacement

- comments and tracked changes;
- compare/review workflows;
- deeper field/content-control support;
- advanced international/accessibility qualification;
- substantially expanded DOCX fidelity corpus.

## R4 — Platform

- capability-based plugins;
- automation;
- collaboration/sync adapters;
- organisation dictionaries/styles;
- optional AI-provider ecosystem.

## R5 — Native engine transition

A native/OpenDoc-derived engine takes authority only feature-by-feature or document-class-by-document-class after explicit compatibility gates. LibreOffice becomes fallback/legacy/oracle infrastructure before eventual removal.

## Future suite expansion

A spreadsheet or presentation editor enters active implementation only after the document product has reached a quality gate where diverting engineering effort will not compromise its trajectory.
